# Toy or Not UI

既存のDesigner素材と紙のパネルを使う。試合状態・設定保存・入力割当は既存のController、GameState、GameUserSettingsを正とし、UIには複製しない。

## 色と文字

共通定義は `Source/ToonStory/UI/TBPaperStyle.h`。元タイトルの黄色・明るいターコイズ・濃茶の輪郭を基準にする。Paper/Creamが面、Inkが本文、Tealが補助操作、Accentがおもちゃ、HumanBlueがにんげん、Dangerが危険操作、Goldが選択・進捗・ホバー。色だけに頼らず見出し・数値・選択マークを併記する。

| 用途 | フォント | 読み込み |
| --- | --- | --- |
| 説明、設定、チャット、操作ヒント | Zen Maru Gothic Medium | `EFontRole::Body` |
| 短い見出し・役割・主要ボタン | Mochiy Pop One | `EFontRole::Heading` |
| 強いPOP表現（既存互換） | Mochiy Pop One | `EFontRole::Display` |
| 遊び方の漫画のセリフ | Yusei Magic | `EFontRole::Hand` |
| 時計・大きなカウンター | Toy UI Numerals（Fredoka 600静的派生） | `EFontRole::Numeric` |

タイトルでは動く部屋の上にSteam用ロゴと3つの表紙ボタンを表示する。ボタンの文言はString TableのFTextで描画する。フォントは `Content/UI/PaperClub/Fonts`、OFLと出典は `Content/ThirdPartyNotices/PaperClub` にあり、Build.csが配布物へ収録する。

## 画面と調整先

- タイトル・検索・遊び方は `TBPaperTitle.cpp` で配置する。タイトルの基準は1600×900。遊び方は1440×810の中に1230×771の漫画を置く。「おもちゃ編」「にんげん編」のタブで写真・見出し・セリフを切り替える。
- ロビー・ステージ選択・試合・結果は `TBPaperHUD.cpp` で描画する。ロビーの基準は1440×810。HUDが使う装飾とステージプレビューは `BeginPlay` で読み込む。
- ポーズと参加者は `TBHUD.cpp` / `TBPlayerSafetyHUD.cpp` で描画する。一時停止の見出しの下に、位置のリセット・再開・参加者一覧のカードを並べる。右下に設定と退出のボタンを置く。
- 設定：`TBOptionsMenu.cpp`、`TBOptionRow.cpp`、`TBKeyRow.cpp`。音・画面・操作・言語で同じパネル寸法を使い、操作一覧はスクロールできる。
- チャット：`TBChatBox.cpp`。長文と長い名前は折り返す。送信者の青い札は陣営を表さない。フェード時も行領域を保持。送信ボタンは既存の入力確定・サーバー検証経路を使う。
- ローディングは `UI/Loading/TBLoadingScreenSubsystem.cpp` と `STBLoadingScreen.cpp` が担当する。アヒル・恐竜・車の3種類に、それぞれ `Content/Movies` 内の動画とポスターがある。最短表示時間はプロジェクト設定の「ロード画面」で調整できる。

`ToonStory.UI.VisualReview.LoadingFilm` を `-UIReviewScreenshots` 付きの描画ありStandaloneで実行すると、各動画の再生・ループとマップ移動時の表示を確認できる。

小さな操作部品は `CompactButtonStyle`、大きい紙カードは `PaperPanel`、HUDの丸角枠は `RoundedPanel` を使う。目標・タイマー・収集カウンター・長押しゲージは支給の構成に合わせる。固定キーを画像に追加せず、既存のKeyLabelを使う。Canvas文字は描画サイズに合わせてラスタライズする。マップ編集は不要。

操作割当は設定の「操作」で確認できる。試合中は対象に近づくと操作と長押しの進捗を表示する。

試合上部の目標・タイマー・カウンターは字幕風に描く。`TBPaperHUD.cpp` の `DrawMatch` で配置し、目標とカウンターの背後に薄い均一な影を敷く。

凝視の演出は `TBGazeHUD.cpp`。おもちゃ側は「ドキッ」などの文字や札を出さず、周辺の影の幅と濃さが滑らかな二拍で変化する。見られている状態から凝視された状態へ緊張が増すと周期が短くなる。既存の警告音は凝視・凍結に入ったとき一度だけ鳴らす。視線が外れたら影は薄れ、Pawnや陣営が変わったら演出状態をリセットする。

人間側の凝視は既存カメラのズームと暗い周辺影で表現し、白い放射状の集中線は描かない。周辺影はカメラの描画範囲であるCanvas内へ収め、黒帯と画面中央の見通しを保つ。

凝視時の画面端の影は、既存の `HumanEdgeStrength` とZoomに連動する係数を0.7から0.86へ上げ、約23%濃くする。影の広さと中央の見通しは維持し、帯の境界では頂点の透明度を補間して段差を出さない。凝視の入力・発動条件・サーバー判定は変えない。

人間の運搬中は `GameState.Box` の収納位置、ママ襲来中はアクティブな `TBMomArrivalZone` の説得地点へ案内する。画面外・背面は左右端の「〈／〉」、画面内は目的地のピンを表示する。通常の札は基準82×26で「箱」「説得」の短い名前だけを添え、距離は表示しない。正面の上下にある目的地は上下端へ寄せた印で示し、横向きの案内と区別する。箱と説得地点が同時に必要な場合は色と縦位置を分け、札同士・中央の照準・収納ゲージを避ける。これは目的地への方角で、障害物を避ける経路探索ではない。

通常の運搬中は下部パネル・進捗バーを表示しない。箱に収納できる位置では、基準156×38の案内札に「E 長押し · 3秒」のように現在の割当キーと必要秒数だけを表示する。収納が始まったら、電池回収と同じ下部の328×76の枠と黄色いゲージを表示し、箱の札は短い名前だけに戻す。進捗は所有クライアントへ複製される `StoreStarted` とサーバー時刻から計算し、取消・収納完了で消える。収納判定は既存の `CanStoreFrom`、説得地点への到着は `ContainsHuman` を使う。ママの「指定の位置に行こう」という中央の案内は削除し、タイマーと説得進捗表示を維持する。案内名と収納文型は日英CSVの `Canvas.BoxDestination` / `Canvas.MomDestination` / `Canvas.StorePrompt` / `Canvas.StoreProgress` で編集できる。

リザルトで本人が勝利している場合は、エモートを促す札とキー一覧を表示しない。エモート操作と勝者のカメラは維持し、観戦中の勝者名・切替案内は必要な場合だけ表示する。

箱に入ったおもちゃの脱出案内は、左上の既存目標札へまとめる。見出しは「脱出」、本文は脱出コースがある場合「上へ登って脱出」、ない場合「仲間の救助を待とう」。画面中央へ別の長文やパネルは追加しない。文言は `Canvas.EscapeGoal` / `Canvas.BoxClimb` / `Canvas.BoxWait` で管理する。

エンジンの診断表示は `TBGameViewportClient` の存続中に抑制し、描画スレッドが遅れて処理するフレームでも一時的に再表示しない。最後のゲームViewportが閉じた時点で以前の状態へ戻す。`tb.EngineWarnings 1` で診断表示を有効化でき、ログ出力は常に残す。エンジン全体の表示フラグなので、同じプロセスのEditorビューもPIE中はこの設定の影響を受ける。

ロビーのゲーム設定・Escから、ステージとルールを編集する画面へ直接入る。ゲーム背景を残した暗幕の上に、黄色い見出しを持つ一枚のクリーム色パネルを置く。この画面にはタイトルロゴを表示しない。左にルール・陣営希望・NPC、右に角丸の大きなステージプレビュー、下にキャンセル／保存を収める。上部の設定ボタンは個人設定、実参加人数／定員のルームボタンは参加者一覧を開く。退出は下部に置き、参加者管理・退出の既存処理を使う。

ステージ選択画面内の「設定」から既存の個人設定画面を開ける。設定画面を閉じると編集中のステージ画面に戻り、ステージ・ルール・NPC人数の下書きと自分の陣営希望を保持する。個人設定の変更・保存は既存のGameUserSettings／設定画面の仕組みに従い、ステージの保存操作と混ぜない。

ルールの編集中はHUD内の一時値を操作し、保存時だけ既存のサーバー検証経路へ渡す。保存・キャンセル・Escで直接ロビーへ戻り、キャンセル・Escでは仮編集を破棄する。ホストのみルールを変更でき、参加人数が変わった場合は現在の人数へ調整して通知する。ゲストの閲覧はホストの保存済み設定へ追従する。自分の陣営希望は従来どおり選択時に反映する。プレビューは既存マップのTBLobbyCameraから撮影した `T_UI_StagePreview_Demo` / `House`。

「NPCを追加」がONのときだけ、トグル直下ににんげん／おもちゃの人数操作を表示する。OFFでは両方の人数を実際に0へ戻し、人数欄を隠す。空きがある状態の初回ONはおもちゃ1人。同じ仮編集中のOFF→ONでは直前の内訳を復元し、両方を0まで減らした場合もOFFとして扱う。記憶はその仮編集内だけで、OFFを保存して画面を開き直した場合は再び初回のおもちゃ1人から始める。空き人数の上限とホスト権限は既存の検証に従い、保存前の人数変更は試合設定へ反映しない。

陣営の人数比を操作する項目は設けない。各自が「にんげん」「おもちゃ」「ランダム」を選び、明示した陣営は必ず尊重する。「ランダム」のプレイヤーだけをサーバーが割り当て、実参加人数と陣営別NPC数を含めて、内部標準のにんげん：おもちゃ＝1：4付近へ調整する。明示選択は標準比率より優先する。全員が同じ陣営を明示選択し、NPCも含めて反対陣営が0人になる場合は、誰かを勝手に反転せず開始不可とする。両陣営がそろうよう選択やNPC数を変更する。配分の正本は `ATBGameMode::SyncLobbyCounts` と `TBRuleMath::AutoHumanPlayers`。

チャットを閉じてもロビーには開くボタンを残し、クリックまたはEnterで既存入力欄を開く。メッセージのフェードと、設定画面を開いている間のチャット非表示は維持する。Canvasの札・丸角は透過三角形と画面約1pxの境界補間で描き、シーン側のアンチエイリアスに依存せず輪郭を滑らかにする。

## 文言とローカライズ

ゲームの設定 → 言語で日本語／Englishを切り替える。選択は既存GameUserSettingsへ保存する。ゲーム本体のUI文言は `Content/Localization/UI/ja.csv` と `en.csv` が正本で、配置・フォント・画像から分離している。Excel等で `SourceString` 列を編集し、UTF-8 CSVとして保存する。`Key` 列は変えず、日英で同じキーをそろえる。ゲームを再起動すると変更が反映される。ブランドロゴの画像はこの文言編集の対象に含めない。

例：`Stage.Title` は「あそびの準備」の見出し、`Canvas.PauseTitle` はポーズ見出し、`Options.Language` は言語欄。文章中の `{0}`、`{1}` などは可変値なので削除・改名しない。翻訳では語順に合わせて移動できる。改行を含むセルはCSVの引用符を保持する。

`UI/TBUIText` がCSVをUnreal String Table `ToyOrNot.UI` として読み込み、UMGは `TBText::Get` のFText、Canvasは `TBText::String` / `Literal` を使う。表示中のUMGも切り替わる。プレイヤー名とチャット入力は翻訳しない。英語の不足項目は日本語へフォールバックする。Build.csでCSVをNonUFSへ収録し、日本語・英語cultureをパッケージ設定に含める。

対応言語はCSVを置くだけでは増えない。CSV追加に加え、TBUITextの許可コード、GameUserSettingsの正規化、設定画面の選択肢、packaging cultureを追加する。本文・見出し・fallbackのフォントが対象文字を収録し、必要なフォントが配布物にも含まれることを確認する。

操作できるモックは `Saved/UIRefresh/MockV2/index.html`。`title-theme.css`で元タイトルの黄色・ターコイズの札と濃茶の輪郭へ寄せ、見出しにMochiy、本文にZen Maru Gothic Medium、数字にToy UI Numeralsを使う。モックのラベルはロゴを除いてすべて描画テキストで、文言は同フォルダの `ja.json` / `en.json`（各100キー）が正本。HTTPで開いた場合はJSONを読み、ファイルを直接開く場合は `locales.js` を使うため、JSON編集後に `build_locales.py` でこのbundleを更新する。ゲーム本体のCSVとモックのJSONは独立しており、自動同期しない。両方に同じ文言変更を反映する場合は、それぞれを編集する。

モックはゲームとは別の見た目確認用で、通信や実設定の保存は行わない。ステージ内の設定ボタンから開いた場合、「適用」「キャンセル」「ステージに戻る」・Escでステージへ戻り、ルール下書き・NPC内訳・個人の陣営希望を保持する。モックの個人設定は即時プレビュー後に「適用」で確定し、「キャンセル」・戻る・Escでは未適用分を取り消す。ゲーム本体の言語設定は選択時に保存する。

モックのNPCは人数欄の展開と保存・取消を試せる。参加者を1人としたプレビューなのでNPCは最大7人で、OFFを保存した後も同じモックを開いている間は直前の内訳を記憶する。ゲーム本体の空き人数や、仮編集を開き直した際の記憶とは区別する。凝視の影はモックでも端の透明度を約25%濃くし、中央の透明領域と集中線の範囲を保つ。

## UI画像の解像度とUMGでの利用

Designer／PaperClubのUIテクスチャは、`SimpleAverage`でミップを作り、`Trilinear`で補間する。`TEXTUREGROUP_UI`の既定設定へ戻すだけではミップが無効になるため、各アセットで明示する。UE 5.8は非2の累乗サイズのミップにも対応するので、余白追加や縦横比変更は行わない。UI用の非圧縮設定・sRGB・NeverStreamを保持し、小さく表示するアイコンには最大サイズ制限を設ける。

タイトルの3種×3状態、主要アイコン、歯車／退出、ポーズのクマを含む20点は支給PNGを参考に高解像度で再作成した。ステージ2枚は既存カメラから3200×1800で再撮影した。これは元の制作データからの再書き出しではなく、細かな線や塗りに差がある。原PNGだけの単純拡大とは区別する。タイトルのブランドロゴは保持する。

9-sliceで使う`Frame_Settings`とPaperClubの`Panel`は、元画像寸法を保持してミップと補間だけ変更する。SlateのBox描画では画像サイズが角の太さへ影響するため、拡大PNGの単純差し替えはしない。吊り札・王冠・チェック・チャットアイコンの再作成候補は透過品質が不足したため採用せず、原画へミップを追加した。

高解像度PNGのローカル制作元は`Content/_Sources/UIRefreshHighRes`（共有対象外）。ゲームは同名の`/Game/UI/Designer/Imported`のuassetを使い、Savedや制作元フォルダーに実行時依存しない。画像の原寸をそのままWidgetサイズにせず、既存の論理サイズとスロット配置を保持する。UMGへ移す場合も画像は装飾、文言はString Table由来のFTextをTextBlockへ渡す。タイトルロゴは画像として扱う。`PauseHeader`はクマだけの透明画像へ変更し、元見出しの文字や雲は含めない。旧画像の画素座標を使う切り抜きも廃止した。

ゲーム内UIにツールチップは付けない。長い名前は省略表示のままで、全文を見せる仕組みは持たない。

## 確認方法

`Scripts/BuildEditor.ps1`でビルド後、描画ありのStandaloneを起動する。撮影fixtureは実通信の検証ではなく、保存なしで表示状態を順に作る。`-UIReviewScreenshots -UIReviewLanguage=ja`（またはen）を付け、画像は `Saved/UIRefresh/ScreenshotsV2/<言語>/<解像度>` に出る。

- `/Game/Maps/TB_Lobby -game -nosteam -UIReviewScreenshots`：`ToonStory.UI.VisualReview.Game`
- `/Game/Maps/Title -game -nosteam -UIReviewScreenshots`：`ToonStory.UI.VisualReview.Title`（検索撮影はLAN/Null限定）

1280×800、1920×1080、2560×1440を起動引数で指定し、日本語と英語で確認する。デスクトップ解像度にウィンドウが制限される場合は、`-RenderOffscreen -ForceRes -ResX=2560 -ResY=1440`を使用し、生成PNGの実寸も検査する。描画検証に`-NullRHI`は使わない。タイトル、検索、ヘルプ、ロビー、ステージ、NPCのON／OFF、参加者、長文チャット、設定4ページ、キー待ち、ロード、両陣営HUD、準備、脱出、ポーズ、結果、8人名札、残り10秒、凝視の周辺演出を含む。撮影用の参加者・発言はStandalone内だけの仮データで、通信せずに表示へ渡す。解像度変更の保持/復帰、キー競合、長い部屋名、実ネット通信はそれぞれ別に検証する。

Title撮影では、タイトル、検索、両陣営の遊び方に加え、主要ボタンのホバー・押下状態を確認する。撮影中だけボタンの操作デリゲートを外し、終了時に復元する。Steam用ロゴの表示、操作部品の文言・ツールチップ、遊び方の吹き出し内に文字が収まることも確認する。

`35-human-gaze` は実Pawn視点で凝視Zoomが最大に達した状態、`36-human-gaze-letterbox` は実Pawnカメラだけを一時4：3に制約し、左右黒帯を出した状態を撮る。初期の凝視入力・カメラ設定・視点は終了時に復元する。後者は通常の確認解像度でクリップを点検するための再現であり、実際の超横長解像度そのものの検証ではない。中央の見通し、黒帯への線漏れ、1280×800でも縮小HUDの文字と数値を読めることは、生成した画像で確認する。

`44`〜`48`はおもちゃのSeen／Gazed／Frozen、解除後、人間へ切り替えた後を撮影する。`49`〜`56`は運搬先の左・右・背面、箱とママの反対側・同じ側・画面内、黒帯、案内解除後を撮影する。箱・携帯ダミー・ママ地点は保存しない一時Actorで、撮影中のみ元の箱参照と携帯状態を差し替え、終了・失敗時に復元する。これは描画の再現であり、実際の収納操作やネット同期・イベント勝敗の試験とは区別する。

`60`〜`64`は収納開始・半分・完了直前・取消後・完了後、`65`・`66`は本人が人間／おもちゃで勝利した結果を撮影する。収納時刻を撮影中だけ補正してゲージ量を維持する。`-UIReviewCompactHintsOnly` を加えると、初期表示と案内・収納・結果の19画面に絞り、`Saved/UIRefresh/CompactHints` に保存する。実際の長押し・取消・完了処理は既存 `ToonStory.Match.StorageHold`、ダミーとの共通状態は `ToonStory.Audio.DummyStoreParity` で別に確認する。

`57`は実際の床へ一時配置したママのクリーム・金色の連続輪、`58`／`59`は箱内の脱出コースあり／救助待ちの目標札を撮影する。`ToonStory.UI.EngineWarnings` はViewportの存続・終了と描画後の診断表示フラグを検証する。ユーザーが見た警告の発生原因自体を解消したと判断する試験ではない。
